# BRZ Garage · 鸿蒙原生版 0.4.0

独立的 HarmonyOS Stage / ArkUI 应用，应用标识为 `com.brz.gauge.garage`。面向 HarmonyOS 5.0+（API 12+）手机。它与原 Android App、BLE 授时桥接应用、仪表固件分别构建和安装。

“轮胎寿命”独立成卡，与“保养项目跟踪”同级；轮胎换位保留在保养项目中。轮胎更换周期保持 50000 km / 8 年。

应用及启动图标统一使用安卓版的黑底红色 STI 原图。

## 已实现

- 按当前安卓版组织为车辆、行程、记账、设置四个页面。
- 用户启用后请求蓝牙权限，扫描兼容仪表，手动选择或输入地址绑定。
- 手动同步结束后断开；启用自动连接后保持蓝牙连接，并在连接期间申请鸿蒙蓝牙长时任务。
- 行程元数据 v1–v4、行程记录 v1–v3、车辆快照 v1/v2 解析及 CRC 校验。
- 新固件从本机游标读取保留的历史，不受另一手机 ACK 进度影响；旧固件给出历史限制提示。
- SQLite 事务同时保存数据和游标，再发送 ACK。CRC 错误、存储失败不会确认未保存的行程。
- 行程列表、中文详情以及迁移过来的加油账本、费用保养、加油区间、自定义行程浏览。
- Android 数据包 v1/v2/v3 导入、v3 导出。完整保留九类数据、允许迁移的偏好、删除标记、拆分行程、手动修正、保养分类、车辆首页与仪表缓存。
- 合并前预览，冲突可选本机或数据包；自动保存并校验导入前备份，可以从历史备份列表逐个导出或再次合并。
- ZIP 路径白名单、数量与大小限制、CRC / SHA-256、字段验证及重复标识检查。

## 0.2.2 首页与界面修正

旧版 Android v1/v2 导出包只包含历史表和白名单配置，不包含 `vehicle_<仪表地址>` 车辆快照、缓存油量和当前加油区间。此前仅验证表记录和偏好一致，并不能证明首页数据已迁移。

无仪表快照时，首页将已导入行程的合计明确标为「已导入行程 · 手机历史合计」；不会把最后一次历史行程当成本次行程，也不会据此伪造剩余油量或仪表 lifetime 累计。连接仪表取得快照后，显示仍以仪表值为准。要离线完整迁移首页缓存，需要另行扩展 Android 导出协议；当前旧数据包无法恢复未包含的数值。

本轮修复主题字体导致的手写体差异、SVG 线框图标错误填充、行程记录月份条与共享指标条、记账分类图标/颜色/占比，修正包已安装，但因手机锁屏，修正后的渲染验收尚待进行。系统字体注册失败时回退到无衬线字体。三个页面仍须逐项完成视觉对照，不把构建通过视为完全复刻验收。

## 0.3.0 完整数据迁移

Android 4.3.0 与鸿蒙 0.3.0 使用 v3 数据包。除原有九类记录和配置外，按仪表保存车辆原始/规范化快照、最后油量样本、当前加油区间、仪表设置原始数据、固件信息和授时状态；车辆外观设置也随包保存。鸿蒙导入后立即恢复首页可用数据，各缓存组按自己的更新时间合并，随后连接同一仪表继续补齐新记录。v1/v2 包继续可读，但因旧包没有这些缓存，导入后仍需连接仪表刷新首页。

### 0.3.1 导入兼容修正

v3 导入会兼容早期导出器写出的数字字符串、布尔值 0/1 和无效的可选传感器哨兵值。无效的可选派生值不会再阻断整包导入；原始仪表报文、历史记录及其他缓存继续保留。必填缓存异常会显示仪表地址和具体字段，便于定位。

## 0.3.2 双向迁移与业务对齐

与 Android 4.3.1 统一使用 v3。修复布局偏好未生效、多仪表缓存归属、峰值与油量序号丢失、仪表新缓存未保存、行程顺序、空里程校准与保养标题；导出前完整校验，并兼容旧版本机元数据缺失缓存字段。检查说明与平台限制见 [对齐记录](../docs/APP_PLATFORM_PARITY.md)。

## 0.3.3 UI 对齐与可见度

逐页检查四个主页面、记账四栏、分组与经典样式、全部设置入口以及详情和编辑弹窗。修复图表和占位文字字体、文字对比度、指标换行、导航选中状态和冷启动缓存统计未刷新；补齐续航计算依据、区间时间与记录说明。鸿蒙真机保存 57 组截图/控件树，82 项回归及双向数据往返通过；检查前后记录、配置和仪表缓存内容哈希全部一致。详见 [UI 检查记录](../docs/HARMONY_UI_PARITY.md)。

## 换机操作

1. 在旧设备导出数据包，传到新手机。
2. 新手机进入「设置 → 应用 → 数据迁移 → 导入并合并数据包」。Android 4.3.0 导出的 v3 包可直接恢复首页缓存。
3. 检查来源、数量与冲突策略，再「确认合并」。默认冲突采用数据包内容，可以切换为保留本机，第一次换机到空库会完整导入。
4. 在新手机启用蓝牙功能并重新绑定仪表。数据包不会自动授予权限或修改绑定。
5. 暂停旧手机的自动连接，在新手机点击首页「立即同步」。

仪表历史容量有限，已被覆盖且未导出的记录无法凭空恢复。旧固件仅提供未确认记录；协议 3+ 支持保留历史的重复读取。仪表 ID 若发生回退会中止同步，需先备份并检查仪表是否重置。

## 构建

用 DevEco Studio 打开本目录，安装相应 SDK，或在 PowerShell 中执行：

```powershell
./tools/build.ps1
```

可传入 `-DevEco '你的 DevEco Studio 安装目录'`。本次使用 DevEco Studio 26.0.0.851、SDK 26.0.0.105、Hvigor 6.26.8 验证构建。

默认产物：`entry/build/default/outputs/default/entry-default-unsigned.hap`。本机签名交付副本位于忽略提交的 `dist/` 目录。

**默认不含签名，因此不能直接作为已签名应用安装。** 在 DevEco Studio 的项目签名配置中，为 `com.brz.gauge.garage` 配置自己的调试签名及测试设备，再构建安装。不要复用其他 bundle 的 profile；证书、口令和本地签名配置不应提交 Git。

## 测试

```powershell
python tools/test.py
```

该脚本先编译生产 TypeScript，运行协议、数据包、合并及同步失败测试，再把生产 Repository.ets 转译到 Node，通过真实 SQLite 执行存储与回滚测试。ArchiveRuntime.ets 也直接转译测试，以真实 DEFLATE 数据配合原生 zlib 的独立计数语义，覆盖正常 Android 压缩包、空内容、Unicode、大压缩率、截断、尾随字节和错误声明大小。Harmony SDK 外壳用测试适配器替代，因此这些测试不能替代手机端 API 联调。

Android 互通测试直接编译 当前原工作区的生产 Kotlin 数据包实现，完成：

`Android 生成 ZIP → 鸿蒙解析/导出 → Android 重新解析并比较所有数据`。

测试所需 Kotlin 和 JSON JAR 从现有 Android 开发环境只读加载；设置 `BRZ_ANDROID_REFERENCE_ROOT` 可改路径，设置 `DEVECO_HOME` 可指定 DevEco。测试不在原 Android 工程写入产物。

## 设备验收

接入测试手机后依次验证：

1. 签名安装、首次启动、权限拒绝与重新授权。
2. 导入 Android v1/v2 数据包，关闭重开 App，核对行程、费用保养及备份导出。
3. 连接仪表授时和读取行程；同步中断开、切后台、重连。

5. 鸿蒙导出回 Android 合并，核对删除和拆分行程。
