## 验证证据

- 最终 127 项宿主运行时测试全部通过，包括“旧自定义分类在精细模式仍可见”的生产页面方法测试。全套日志位于 `tmp/harmony-0.5.0/tests.log`。
- 生产页面方法测试覆盖精简保险选择、普通日期恢复、清除日期后重复切换以及未知旧分类；不是仅匹配页面文案。
- 通知测试转译生产 `.ets`，覆盖并发去重、跨紧迫程度更新、发送失败后重试、拒绝权限／撤回同意、删除旧周期和后台任务注册。
- 生产 Kotlin → Harmony → Kotlin 数据包往返通过，比较九类表、偏好、车辆缓存；鸿蒙新建资产／移除／出售删除标记及注册资料被 Android 生产解码器正确读取。
- 最终真实数据库链路：Android 生产存储 → Harmony 生产 Repository → 新 Android 生产存储，33 个迁移场景通过，含重启、重复导入、稳定 ID、离线首页、绑定前费用及自定义历史。日志：`tmp/harmony-0.5.0/android-store-roundtrip.log`。
- ArkTS 与 HAP 构建通过。包内 `versionName=0.5.0`、`versionCode=500`，包含 `LedgerWorkAbility`；继承 API 12 最低版本和原 PartnerAgent 能力。
- 沿用原私有调试签名；HAP 摘要与签名校验通过，证书链 SHA-256 与原 0.4.0 相同。未安装、未清除手机数据、未发布、未刷写仪表。
- 完成变更源码审阅后更新 57 个 Android 文件的漂移基线，并纳入新增注册资料／期限／提醒文件。该基线是源码审阅记录，不是屏幕像素验收记录。

## 平台边界与设备验证

Android Kotlin/View 与 Harmony ArkTS/ArkUI 不是相同运行时。系统日期选择、权限、文件选择、后台调度、应用升级采用各平台原生机制；Android APK 更新器不用于 HAP，JobScheduler 对应 Harmony WorkScheduler。

用户本轮暂不具备设备条件，因此没有执行两端真机截图、触控、通知实际送达、系统重启恢复及 BLE 实机验收。源码复现与宿主测试通过不能证明像素级一致，也不能证明后台任务一定准点送达。原有平台差异及这些验收边界继续保留，不改写为“已实测”。

交付包：`harmony_app/dist/BRZ-Garage-Harmony-0.5.0-debug-HED-signed.hap`；对应 SHA-256 文件位于同目录。此为原测试设备授权的私有调试包，沿用既有签名范围。
