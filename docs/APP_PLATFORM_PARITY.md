# 安卓与鸿蒙对齐检查（2026-10-08）

检查对象：主工作区 Android 客户端，以及 `codex/harmony-app` 工作树中的 `harmony_app` 原生客户端。`harmony_ble_bridge` 是授时辅助，不是本次对齐对象。修复版版本为 Android 4.3.1 / 鸿蒙 0.3.3，继续使用各自原应用标识。迁移与业务修复在鸿蒙 0.3.2 验证，后续 0.3.3 全面 UI 检查及修复见 [UI 检查记录](HARMONY_UI_PARITY.md)。

## 本次发现与修复

| 项目 | 原来的差异或故障 | 修复后的行为 |
| --- | --- | --- |
| 数据包版本 | 主目录安卓只能接收 v1/v2，鸿蒙已导出 v3 | 两端使用 v3，继续读取 v1/v2；升级旧安卓后才能接收鸿蒙导出 |
| 首页数据 | v2 不含实时快照的离线缓存 | v3 携带车辆、最近油量、当前加油区间、仪表设置、固件和授时缓存；按缓存组的更新时间合并 |
| 布局偏好 | 鸿蒙把经典首页/经典设置存为私有元数据，导入偏好没有改变正在显示的布局 | 偏好与数据同一事务提交，导入、修改、重启、再次导出一致；空值恢复默认布局 |
| 多仪表缓存 | 未绑定时先导入 A 再导入 B，B 的缓存可能被投影到 A 地址下 | 活跃首页只使用合并结果的活跃地址；其他仪表的缓存保留在各自地址下 |
| 车辆峰值 | 鸿蒙新快照不携带车速/转速/加减速峰值和油量样本序号 | 实时解析、缓存、重启、导出均保留这些字段，安卓可以重建对应车辆报文 |
| 仪表信息 | 鸿蒙只保存导入过的设置/固件/授时，自己读取的新值不进入数据包 | 同步和设置回读更新对应缓存；离线仪表页读取缓存并标明上次读取时间 |
| 行程顺序 | 鸿蒙按结束时间排序，未授时及人工修订会改变记录位置 | 与安卓按行程序号倒序排列，拆分子行程 B 在 A 前，时间修订不改变发生顺序 |
| 里程校准 | 导入空校准值但保留旧锚点时，鸿蒙漏计旧行程 | 空值按未校准计算，显式零校准值仍作为有效校准 |
| 保养标题 | 鸿蒙没有兼容旧记录中直接写为 A保/B保的标题 | 与安卓使用同一标题推断；手动保养类型优先 |
| 合并预览 | 鸿蒙漏计同时间戳的仪表缓存冲突，默认冲突策略也不同 | 两端均计入冲突，默认采用包内内容；可以选择保留本机 |
| 文件保存 | 先创建目标再生成数据，生成失败可能留下空文件 | 先生成并解析验证，再打开保存窗口；鸿蒙备份导出同样校验 |
| 鸿蒙旧数据升级 | 旧版本机元数据没有后来新增的缓存字段，升级后导出报油量缓存无效 | 打开数据库时为缺失缓存补上默认空值，保留原历史数据；新增旧元数据导出和导入前备份回归测试 |
| 安卓文件选择 | MIME 过滤可能隐藏文件提供方识别成其他类型的 ZIP | 允许选择文件后按真实包内容校验；无文档选择器时尝试普通文件选择器 |

## 检查范围

车辆、行程、加油、保养、日常支出、统计、车牌、仪表设置、自定义区间、加油区间和迁移入口按源码逐项检查。鸿蒙冻结参照中的 Android `MainActivity.kt`、行程列表、驾驶日历、设置图标和车牌编辑源码仍与当前主工作区一致；本次改动后的迁移页独立验证。

跨平台往返测试编译当前主工作区的生产 Kotlin 编解码代码，而不是只编译冻结参照文件。测试覆盖九类表、中文和非 BMP 字符、偏好、删除标记、拆分、修订、仪表缓存与 SHA-256，并由安卓再次解析鸿蒙输出包。两端真实 SQLite 宿主测试覆盖事务回滚、备份失败、重复导入、重启和跨仪表数据隔离。鸿蒙文件 API 适配测试模拟短读/短写与多个 64 KiB 边界。

这不等同于所有页面已经经过真机视觉验收。3D 车辆继续沿用鸿蒙项目原先“暂不实现”的范围。Android 系统伴生唤醒、开机广播、APK 更新器与鸿蒙的长时蓝牙任务、生命周期、HAP 安装机制存在平台差异；系统杀进程后鸿蒙静默唤醒尚未实现。不得将其写为已完全相同。

## 验证结果

- 鸿蒙：73 项生产代码与真实 SQLite 宿主测试通过，当前安卓编解码器往返九类记录、偏好和设备缓存通过；ArkTS HAP 编译成功。
- 安卓：23 项迁移宿主场景、40 项相关功能检查通过；APK 构建成功，13 项离线车辆资源核验通过。
- 鸿蒙真机：使用原 0.3.1 签名覆盖升级至 0.3.2。升级前后的 SQLite 完整性检查通过，204 条记录、23 项偏好及本机元数据的内容哈希一致。
- 实际文件流程：系统保存窗口成功保存约 52.7 KB 的 ZIP，系统选择器再次选取该包，校验和合并成功；预览新增/更新/删除/冲突均为 0。确认合并时自动生成备份。
- 重复导入后再次读取真机 SQLite：204 条历史记录与升级前逐行完全一致，原 23 项偏好值全部保留，新增 6 项布局/外观偏好，保存 1 份仪表缓存。当前 Android 4.3.1 生产解码器成功读取真机生成的导入前备份 ZIP，九类记录计数与数据库相符。
- 没有连接安卓测试手机或车辆仪表。本轮安卓文件提供方实机行为，以及两端真实 BLE、后台长时运行和 OTA 未实测。临时延长的测试手机息屏设置已恢复。

## 使用

1. 将安卓升级到 4.3.1，鸿蒙升级到 0.3.3；覆盖安装应保持各自原签名，不先卸载。
2. 旧手机完成同步，打开“设置 → 应用 → 数据迁移 → 导出完整数据包”，保存并传送 ZIP。
3. 新手机选择“导入并合并数据包”，核对来源、导出时间、记录和冲突；通常采用包内内容，确认后会先保存本机备份。
4. 在新手机重新授权并绑定原仪表。导入不会迁移绑定、权限、用户同意、自动连接开关和待执行命令。
5. 旧手机暂停自动连接，再在新手机同步。v1/v2 包没有仪表缓存，需要连接仪表刷新首页。

包未加密。备份合并不会删除随后新增的记录，不能当作整库回滚。
