# BLE 手机同步协议

仪表在 Device Info Service `0x1FFA` 中提供手机授时和行程同步。所有多字节整数均为小端序，时间为 Unix UTC 秒；手机负责按本地时区显示。

## 特征

| UUID | 方向 | 用途 |
|---|---|---|
| `0x0002` | 手机写入 / 读取 | 8 字节 Unix 秒；写入校准，读取确认本次开机的当前时间，未授时返回 0 |
| `0x0003` | 手机读取 | 20 字节同步元数据 |
| `0x0004` | 手机写入 | 5 字节游标或 ACK 命令 |
| `0x0005` | 手机读取 | 下一条行程记录：v1 为 40 字节，v2 为 48 字节 |
| `0x0006` | 手机读取 | 64 字节车辆快照（新增，可选，旧固件没有此特征） |
| `0x0007` | 手机读取 | 104 字节仪表设置快照 v1（只读；没有 WRITE 权限） |
| `0x0008` | 手机写入 | 6 字节亮度设置命令（只写；仅开放 10%～100% 日间亮度） |
| `0x0009` | 手机写入 | 6 字节车型设置命令（只写；仅允许 ZC6=1、ZD8=4） |
| `0x000A` | 手机读取 / 写入 | 12 字节里程显示与校准快照/命令 |

元数据字段依次为：协议版本 `u8`、待同步数量 `u8`、曾溢出 `u8`、保留 `u8`、最旧 ID `u32`、最新 ID `u32`、最后 ACK ID `u32`、队列容量 `u16`、记录长度 `u16`。

控制命令为 `command u8 + trip_id u32`：`1` 表示读取 ID 大于 `trip_id` 的第一条记录，`2` 表示手机已持久化到该 ID，可以从仪表队列删除。

行程记录 v1 字段依次为：版本 `u8=1`、标志 `u8`、长度 `u16=40`、ID `u32`、开始时间 `u64`、结束时间 `u64`、时长秒 `u32`、里程米 `u32`、燃油毫升 `u32`、平均油耗乘 100 `u16`、CRC16-CCITT `u16`。

行程记录 v2 保持上述前 38 字节不变，然后追加最高速度 `u16`（km/h）、最高转速 `u16`（rpm）、最大加速 `i16`（m/s² ×100）、最大减速 `i16`（m/s² ×100），最后是 CRC `u16`，总长 48 字节。CRC 初值为 `0xFFFF`、多项式为 `0x1021`；v1 覆盖前 38 字节，v2 覆盖前 46 字节。标志 bit 0 为时间有效。元数据的协议版本/记录长度组合为 v1/40 或 v2/48，手机必须按该组合执行 Read Blob 分片和解析。

平均时速不占用协议字段，由手机按 `distance_m × 3.6 ÷ duration_s` 计算；`duration_s` 是发动机有效运行时间，因此中途怠速也计入分母。加速度由仪表使用连续 OBD 整数车速样本与实际采样间隔估算，并过滤绝对值超过约 3 g 的跳变。它适合驾驶回顾，不属于高频 GPS/IMU 测量。

## 同步顺序

1. 手机连接后先写 `0x0002` 自动授时（优先于 MTU 协商和行程下载）。若特征支持 READ，再回读检查与手机 Unix 秒相差不超过 5 秒；不通过则断线重试。旧固件只记录“写入确认”，不显示“已校验”。
2. 读取 `0x0003`，以 `last_ack_id` 作为游标。
3. 写命令 `1 + cursor`，再读取 `0x0005`。
4. 手机校验 CRC，并用 `(device_id, trip_id)` 主键写入本地数据库。
5. 重复步骤 3–4，直到最新 ID；最后写命令 `2 + newest_id`。
6. 首次车辆快照完成后读取一次 `0x0007`。同一条 BLE 连接中不重复读取设置，断线重连后重新取当前值。
7. 用户主动应用亮度、车型、里程显示或里程校准时，手机保存最后一次请求，等待上述同步链路进入空闲后再写对应特征并回读确认；这些请求不抢占授时、行程 ACK 或车辆快照。

只有第 4 步已成功持久化后才能 ACK。固件只接受本次连接中已经实际读取过、且不超过当前最新记录的 ID。这样即使 BLE 中断或应用被结束，下一次连接仍可安全重传；手机数据库的联合主键会去重。

仪表保留最多 64 条“尚未被手机确认”的记录。确认后完整历史由手机数据库长期保存。若 64 条队列在同步前已经装满，仪表会丢弃最旧的未确认记录，并在元数据中置位 `overflowed`，手机应向用户显示警告。

## 车辆快照 v1（64 字节）

所有字段为小端序；CRC 算法与行程记录相同，覆盖前 62 字节。ATT 长读取在 offset=0 时取快照，后续片段保持相同内容。

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0 | u8 | 版本 1 |
| 1 | u8 | 标志：bit0 油量有效，bit1 转速/速度新鲜，bit2 本次开机已授时，bit3 累计均耗有效 |
| 2 | u16 | 长度 64 |
| 4 | u64 | 当前 Unix 秒，未授时为 0 |
| 12 | u32 | 本次开机运行秒数 |
| 16 | u16 | 油量百分比 ×100；无效为 65535 |
| 18 | u16 | 累计平均油耗 L/100km ×100 |
| 20 / 24 / 28 | u32 各一个 | 本次行程米数 / 秒数 / 燃油毫升 |
| 32 / 40 / 48 | u64 各一个 | 仪表累计米数 / 秒数 / 燃油毫升（不是 ECU 原车里程表） |
| 56 / 58 | u16 各一个 | RPM / km/h，仅 bit1 有效时代表新鲜数据 |
| 60 | u16 | 保留 0 |
| 62 | u16 | CRC16 |

油量通过 `01 2F` 采集，每 30 秒最多一次；连续三次探测无有效回复后暂停到下次 ELM 初始化。成功后持续低频采样，超过 90 秒或 ELM 断开则标记无效。

手机按油箱容量（默认估算参数 50 L，用户可校准）计算升数，按仪表累计均耗计算续航。累计样本不足 10 km、油量未知、均耗无效时显示不可用。该值是估算，未获得 ZD8 实车 PID 2F 支持验证。

## 仪表设置快照 v1（104 字节，只读）

`0x0007` 只声明 READ 属性，固件没有对应的设置写入处理。手机仅在每次连接后读取一次。offset=0 时，固件把已经加载在 RAM 中的配置复制到固定缓冲区并计算 CRC；后续 ATT Read Blob 分片读取同一份缓冲区。此过程不读取或写入 NVS、不切换页面、不暂停 OBD/ELM327 采集，也不改变仪表运行状态。

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0 / 1 | u8 / u8 | 版本 1；标志 bit0=只读、bit1=行程合并间隔被固件锁定 |
| 2 | u16 | 长度 104 |
| 4～15 | u8 各一个 | OBD 协议、主题、默认页、亮度、车型、仪表角色、联动动画、仪表位置、转速闪烁、联动闪烁、RaceChrono、启动画面 |
| 16 / 18 / 20 / 22 | u16 各一个 | 刹车温度提醒 °C、机油压力提醒 ×10、转速提醒 rpm、行程合并分钟数 |
| 24～26 | u8[3] | TEMP 页显示项 |
| 27～31 | u8[5] | INFO 页显示项 |
| 32 / 33 | u8 / u8 | 指针页数据项、图表页数据项 |
| 34～39 / 40～45 | byte[6] / byte[6] | ELM327 MAC、已绑定主表 MAC |
| 46～77 | char[32] | ELM327 名称，NUL 结尾/填充 |
| 78～101 | i16[12] | CLT～AFR 图表报警原始阈值；32767=关闭 |
| 102 | u16 | CRC16-CCITT，覆盖前 102 字节 |

当前 Android 页面会用选择框、开关和数值框展示这些参数。未收到快照时显示等待占位，连接后填入实际值；除日间亮度外，所有控件仍被禁用。`0x0007` 本身始终只读，亮度修改使用下面独立的 `0x0008`，不能把设置写入混入快照特征。

## 亮度设置命令 v1（6 字节，只写）

`0x0008` 只声明 WRITE 属性。数据依次为：版本 `u8=1`、命令 `u8=1`（SET）、亮度 `u8`（10～100）、总长度 `u8=6`、覆盖前四字节的 CRC16-CCITT `u16`。范围、长度、版本、命令或 CRC 任一不合法时，仪表拒绝写入。

固件的 GATT 回调只执行定长校验并用无等待队列提交事件，不在蓝牙任务中操作屏幕或 NVS。仪表 UI 任务串行应用亮度并保存用户配置；该过程不重启 BLE、ELM327 或 OBD 采集，不读写、重置或清除行程与油耗统计。事件队列满或回读不一致时手机有限次数重试亮度操作，达到上限后只报告亮度失败，正常数据连接继续运行。

OTA 的 `OTA1/4` 手动启动命令同样不能在 GATT 回调中执行耗时的 Wi‑Fi 初始化。3.1.1 起，回调只安排一个幂等的一次性任务并立即返回写入确认；任务稍后暂停采集并启动 SoftAP。为兼容较早固件可能已经启动热点却丢失 BLE 回调的情况，Android 会搜索 `OBD-Gauge-OTA-*`，使用固定引导口令加入后从未鉴权的 `/ota/discover` 读取本次随机令牌，再复核 `/ota/info` 设备清单。后续上传、状态和取消端点仍必须携带随机令牌。

## 里程显示与校准 v1（12 字节，读写）

`0x000A` 的读取快照依次为：版本 `u8=1`、标志 `u8`（bit0 显示、bit1 已校准）、总长度 `u16=12`、当前里程 `u32`（0.1 km）、保留 `u16=0`、覆盖前 10 字节的 CRC16 `u16`。

写入命令也固定为 12 字节：版本 `u8=1`、命令 `u8`、显示值 `u8`、总长度 `u8=12`、校准里程 `u32`（0.1 km）、保留 `u16=0`、CRC16 `u16`。命令 1 修改显示状态并使用显示值 0/1；命令 2 校准里程并使用 `u32` 数值。非法版本、长度、范围、保留位或 CRC 会被拒绝。

仪表把里程配置保存在独立 NVS blob 中，不改变已有用户配置和行程存储布局。当前值由“校准基准 + 仪表累计行程相对增量”计算；未校准时显示仪表自身累计行程估算。BLE 回调仅校验并无等待入队，由 UI 任务执行单次用户触发的保存；不新增 OBD 请求、采集任务或周期性 Flash 写入。App 的待处理修改在正常同步空闲后发送，再读取同一特征确认；失败只影响本次设置，不重建健康的数据链路。

## 自动发现与运行限制

- 固件取消原来的两分钟窗口及授时后的广播关闭，上电期间未连接时持续以 500～750 ms 间隔广播；离开 OTA 页仍保留手机发现能力。
- 手机首次由用户选择仪表并保存地址，之后只连接该地址；不按名称自动连接附近任意仪表。
- Android 12+ 优先使用系统 Companion Device presence 回调唤醒；不支持的系统使用常驻 connectedDevice 前台服务与地址过滤扫描。
- 连上后先授时并回读，再同步历史、车辆状态及一次只读设置；车辆状态前台 15 秒、后台 30 秒，历史约 60 秒检查一次，时间每 10 分钟重新校准。每次重连都立即重新授时。
- 每项 GATT 操作有 25 秒超时，连接失败后 2～30 秒退避；陈旧连接回调被忽略，读写返回失败不会误显示同步成功。
- 本地 SQLite 成功写入后才能 ACK，协议和数据库主键不变。手机新版本不会伪造旧行程的现实时间，驾驶时长明显大于起止跨度时显示异常。
- Android 3.1.0 同时接受 v1/40 与 v2/48；数据库原地追加详情和本地修订标记。旧固件记录以及升级前已排队的记录会保留，但没有采集过的极值显示为不可用。测试修订只改手机副本，同一行程重传不会覆盖，也不会反写仪表。
- 自动唤醒不等于系统允许强制停止后运行。后台权限、蓝牙开关、省电策略、设备固件广播及 BLE 连接资源仍是前提。

## 延迟授时的行程边界估算

手机无需在发动机启动瞬间连接。本次仪表上电期间，固件以 `esp_timer_get_time()` 保存第一次和最后一次有效发动机运行采样的单调时钟锚点；RPM 有效且大于 0 即累计驾驶时长，不再要求 MAF、PID 5E 或速度同时有效。

手机以后首次或再次成功授时时：

- `结束时间 = 手机时间 - 最后一条发动机运行数据距现在的单调时间`，因此停车后才连接不会把等待连接的时间算进驾驶结束时间。
- `开始时间 = 结束时间 - max(首末发动机采样跨度, 累计发动机运行时间)`。首末跨度可保留中途短暂 OBD 丢包；累计运行时间作为下限，保证不会再生成“起止跨度短于驾驶时长”的记录。
- 断电后的合并窗口用“上次行程结束 → 本次上电后实际开始驾驶”的间隔判断，不再用可能延迟很久的手机连接时刻。因此设定 15 分钟时，4 分钟后重新驾驶但 25 分钟后手机才连接，仍会判为同一行程。
- 若手机做出合并/拆分决定前发生 USB 串口复位或其他额外重启，待判定行程会继续保留，不会因“第二次开机”被提前固化成独立记录。
- 同一上电周期的后续授时会重新估算，允许系统时钟修正。若已合并上一断电周期且旧记录有有效开始时间，则保留更早的真实开始时间。
- 单调锚点不写入 flash；它的数值在完全断电后没有意义。若从行程开始到仪表断电都从未成功授时，下一次上电仍无法知道断电空档的绝对时间，旧段只能保持“时间未知”，不能安全伪造。

实现位于 `main/app_obd_dsp/trip_time_anchor.c` 与 `main/bsp_obd_dsp/nvs_storage.c`。主机测试包含延迟授时、停车后授时、累计时长下限、无锚点回退、非法时间拒绝和基于实际开始时间的合并窗口。

Android 官方依据：[后台 BLE 通信](https://developer.android.com/develop/connectivity/bluetooth/ble/background)、[伴生设备绑定](https://developer.android.com/develop/connectivity/bluetooth/companion-device-pairing)、[蓝牙权限（含 Android 10/11 后台定位）](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)。
