# Android 4.4.0–4.4.2 记账测试版

- 日期：2026-10-30；versionCode：154；内置固件未调整。
- 安装包：`android_app/BRZ-Garage-v4.4.0-debug.apk`。覆盖安装保留本地数据，不要先卸载。
- 入口：记账 → 顶部「切换至精细版」。原有用户默认精简版。

## 本次实现

精简与精细界面共用记录、ID、金额和删除状态。精细版的三栏为加油、固定开销、日常；统计从顶部进入。固定开销含保养/维修、保险、年审、证件手续、资产/配件用品。日常分收入与支出，收入不混入支出图表；净支出单独显示。

保养/维修有两个录入入口、历史筛选与分项费用。顶部突出最近剩余公里和月份，两个维度可能来自不同项目，分别标注。没有实际保养日期时不推测时间；没有里程时提示补充。普通维修内容写入项目说明，不触发保养周期；勾选实际完成的保养项目才重置该项目。

保险、年审和证件手续提供可选到期跟踪；免费办理可填 0 元。4.4.0 按同名项目的最新记账日期取周期，4.4.1 改为下面的日期规则。

## 4.4.1 中国大陆保险与年检追踪修正

2026-10-30 核对官方公开资料；版本 4.4.1 / versionCode 155，沿用现有签名及固件，安装包 `android_app/BRZ-Garage-v4.4.1-debug.apk`。

保险以保单起止日期判断，付款时间只用于记账。交强险、商业险分别追踪，常见同义名称归一；公司变更不另建周期，其他险种按名称分开。同险种当前保障仍展示；提前购买的后续保单只有明确起止日期且按日期连续时才合并后续提醒。未来保单显示待生效；存在空档或缺失日期时，保留已知到期提醒，提示核实。数据仅精确到日，不能判断具体小时的空档、退保或保险公司承保状态。

交强险是强制投保项目；条例第十九条要求到期及时续保，第二十条规定通常一年并有短期例外，故不强制把所有保单算成一年。商业险是另行订立的合同，保障范围及期限按实际保单；App 的提前提醒不是法定宽限期。[国务院《机动车交通事故责任强制保险条例》第二、十三、十九、二十条](https://www.gov.cn/gongbao/content/2016/content_5139679.htm)。

年检按每辆车的实际检验有效期止追踪，输入月份统一取月末；未办理前不因今天日期变化自动推进周期，费用记录也不等于办结。用户可明确选择「常规私家车检验」，填写行驶证初次注册日期。仅9座及以下非营运小微型客车（面包车除外）采用辅助规则：第2、4、8年免上线但仍须领标，第6、10年上线，超过10年每年上线；人员伤亡事故、非法改装被处罚等特殊情形不套用常规规则。旧手工名称或信息不足的记录保留手工追踪，办理方式提示待核实。计算与实际有效期不一致时，以交管12123为准，不强行改动。[益阳市政府公开的公安交警政策说明](https://www.yiyang.gov.cn/yiyang/2/12728/content_1885457.html)。

提前办理窗口包含到期当月共3个自然月（例如11月到期，从9月1日起办理），不是机械减90天。[北京市石景山区政府办理说明](https://www.bjsjs.gov.cn/gongkai/zsk/jjjt/jtcx/202103/t20210311_50249.shtml)。办理前应处理相关违法和事故，免上线领标也需要交强险凭证、车船税纳税或免税证明；App 只提示核对，不自动推定交管系统已经审核通过。[《机动车登记规定》第五十四至五十六条](https://www.gov.cn/gongbao/content/2022/content_5682413.htm)。

存储继续使用既有 v4 字段：仅当年审项目明确选为「常规私家车检验」时，`start_epoch_day` 表示初次注册日期，`due_epoch_day` 是交管实际检验有效期止；旧名称不自动改成常规规则。办理完成后可以从上一个有效期参考下一周期，仍需用户核对保存。原有任意项目名称保持原值，险种同义词仅在派生跟踪时归一。两端迁移继续保留这些字段，鸿蒙尚无此追踪页面和通知实现。

## 通知验证

4.4.2 新增车辆信息入口：设置 → 我的车辆 → 车辆设置 → 车辆注册登记与年检。填写行驶证初次注册日期并确认常规私家车适用条件后，自动给出预计检验有效期止；初次估算假定往期已经办结，按本年或后续适用节点计算，本年已过的到期月仍显示逾期。实际有效期可以按交管12123校准。保存后固定该到期日，日历翻年不会自动推进；点击「本次已办结」才会参考上期有效期生成下一期，并核对保存。特殊车辆不套用常规计算。

注册资料独立存放在每辆车的 `vehicle_registration_<仪表地址>` 配置中；未绑定时暂存为 `vehicle_registration_local`，首次选择仪表时只归属该车一次。数据包携带 JSON 字符串，其中包含初次注册日、规则选择、当前待办有效期及是否估算。新 Android / Harmony 编解码器均允许这些配置键；旧版 v4 客户端可能因不认识新配置键而拒绝导入。年检费用仍单独记账；车辆信息已有有效期时，以车辆信息的待办为主，不以付款日期推进年检。

4.4.2 保险自动日期：新投保默认用记账日期预填保障开始日，提前续保预填上一期到期次日；旧保单已过期时，用本次记账日期预填，不自动回填过去的保障日。开始日加一个日历年减一天作为包含当日的参考终止日。修改起保日时，自动计算状态下同步更新终止日；直接修改终止日后保留手工值，支持短期与特殊保单。付款日与实际保障开始日独立，提前投保须核对实际生效日，具体起止时刻与保险期间以保单约定为准。

记账顶部可开启「保险、年检与保养通知」。通知需要系统授权，渠道名为「保险、年检与保养提醒」。应用打开、记录变化和后台定期任务均检查最新到期计划；后台约每 6 小时检查一次，不依赖仪表连接，系统重启后继续调度。系统省电、禁止后台或强行停止会影响实际送达，未做真机后台时效验证。

4.4.1 在剩余30、7、3天、当天及逾期阶段提醒，每个项目、周期、阶段去重；错过某一天后，在当前阶段补发一次，不重放所有旧节点。年检增加办理窗口开启提醒，通知标题区分免上线领标、上线年检或待核实；同次项目合并为一条通知。连续续保/新保养记录重新计算，旧周期消息相应移除。只有里程周期而没有日期周期的项目不会推测「提前几天」。这是App提醒策略，不是法定期限。

建议测试：
1. 记一笔 0 元商业险，将到期日设为今天或 3/7/30 天后；保存后检查通知。
2. 使用「记录续保」保存同名商业险，填明确且连续的保障起止日期；旧提醒应消失。留出空档或缺少生效日时旧提醒仍保留。
3. 增加交强险，确认商业险续保不会取消交强险提醒。
4. 记录机油保养，日期设为六个月前对应提醒节点；再记录实际完成的机油更换，确认旧周期停止。
5. 普通维修不勾保养项目，确认原来的保养提醒仍保留。
6. 切换精简/精细，修改金额或备注，确认险种、起止日期、公司等仍保留。
7. 导出完整数据包，在支持 v4 的版本恢复，重复导入不增加记录数。
