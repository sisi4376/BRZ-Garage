# OBD 轮询自检（4.0.2）

入口：历史行程详情 → 修订测试数据 → 查看 OBD 轮询自检结果。打开子页面不会丢失修订表单的未保存输入。

每个项目分为已收到响应、已请求但未收到有效响应、未请求；升级前的旧行程显示未记录。有效响应指有完整、可解析的数据字段，零车速也是成功。该标记不表示持续在线、数值准确或 A4 已识别出具体挡数。能力查询未通过、车型不适用和短行程都可能造成未请求。手动拆分的行程继承原始整条行程的标记，不能据此判断拆分前后分别收到过什么。

## 采集成本和边界

- ELM 发送成功后记录请求，现有响应解析后记录成功；不新增自检 PID、任务、日志、定时器或实时 BLE 通知。
- 回调只更新两个 32 位原子位图，不分配内存、不调用 NVS、不等待存储锁。统计任务取出事件，合并到当前行程。
- 复用原来的行程检查点写入和历史同步，每条行程增加 8 字节。重连保留本行程已有成功标记；跨上电合并行程时按位合并，队列淘汰时标记与行程一同移动。
- 默认采集恢复 4.0.0 的空闲挡位槽，不发送 `01 A0`／`01 A4`。被动自检记录保留，未发送的项目显示未请求。仅显式启用 `CONFIG_OBD_EXPERIMENTAL_GEAR_POLL` 的测试固件会使用 ELM 带宽：先以至少 5 秒间隔查询 `01 A0`（最多 3 次），声明支持 A4 后，以至少 2 秒间隔查询 `01 A4`。连续 3 次无完整响应后停用到重新初始化；不追赶错过的轮询，也不扫描厂家 DID。
- ZC6 和 ZD8 保留上述 A4 解析能力；A4 比值仅在响应声明支持比值、车辆移动且比值连续匹配时参与原有挡位策略。没有确认 BRZ 实车支持 A4；默认继续使用原来的推挡方式。
- 原厂里程 A6 保持停用。诊断结果仅随已归档行程同步；本次实时快照不增加载荷。

## 持久化和协议

固件 fuel_store_t 和 trip_sync_store_t 只在尾部追加健康记录，原有结构及数组元素大小不变；旧 NVS blob 新增尾部为零。沿用现有存储版本与 grow 加载策略。App 数据库升至 v6，新增 poll_requested、poll_received，默认零；修订不能手动改写采集证据，重复同步按位合并。

元数据版本 v4、recordSize=56；记录版本 v3。v3 保留旧版记录前 46 字节：offset 46 为请求位图 u32，offset 50 为收到响应位图 u32，offset 54 为 CRC16（覆盖前 54 字节）。全部小端。

请求位图 bit 31 表示存在自检记录；没有此标记表示旧记录，不能显示为失败。其余位的定义与 Android PollHealth.items 一致：

| bit | 请求 |
|---|---|
| 0–7 | 010C、010D、010F、0105、015C、0142、0104、0111 |
| 8–14 | 0103、0144、0110、012F、015E、01A4、2101 |
| 15–17 | 0100、0140、01A0 |

新 App 兼容旧元数据 v1/40、v2/48、v3/48 和记录 v1/v2。旧 App 不识别新元数据 v4，应先更新 App 再通过 App 更新仪表；没有发布、自动安装或自动烧录。

## 验证

`tests/test_obd_poll_health.py` 直接编译运行生产 C 自检模块和提取的调度／队列函数，覆盖零值、残缺响应、取出合并、限频、重试上限、队列淘汰对应关系。

`tests/PollHealthProtocolHostTest.java` 对实际编译的 App 类运行，覆盖旧／新记录、CRC 损坏、无符号位图、状态标签、元数据长度匹配。另运行现有行程协议和挡位回退测试。

尚需实车检验 PID 支持情况与端到端采集速率；主机测试不能证明车辆会回复 A4。
