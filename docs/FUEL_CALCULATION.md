# 当前油耗计算方法（2026-09-04）

借鉴 Car Scanner 开发者公开的“进气量估算 + 燃油系统状态辅助判断零油耗”思路，不是其当前算法的复制，也未完成 ZD8 实车标定。

## 数据来源与显示

油耗页标题标出当前来源：

- `FUEL / ECU`：优先使用有效的 `01 5E`，返回值每单位 0.05 L/h；有效零值保留，估算规则不得覆盖它。
- `FUEL / MAF`：使用 `01 10` 进气流量和 `01 44` 指令空燃比换算燃油流量。公式为 `L/h = MAF(g/s) × 3600 ÷ AFR ÷ 745`；汽油密度假设 745 g/L，AFR 无效时回退 14.7。并非喷油实测。
- `FUEL / CUT EST`：没有有效 5E、但状态和其他信号共同支持滑行断油时，按零燃油流量估算。`EST` 明确表示推断。
- `FUEL / OFF`：新鲜 RPM 为零，不累计燃油、里程或发动机运行时间。
- `FUEL / NO DATA`：缺少有效基础数据，不把缺失数据当作零油耗，也不补算该时间段。

车速低于 3 km/h 显示 L/h，否则显示 L/100km。当前行程和 Lifetime 平均值仍分别来自同一组累计燃油量与里程之比，不是瞬时百公里油耗的算术平均。

## 断油判断

新增轮询 `01 03`，解析第一个燃油系统状态。状态 4 同时可能表示大负荷开环加浓或减速断油，不能单独当作“停止喷油”。

只有状态恰好为 4，且以下条件同时满足，才进入 `CUT EST`：

- 车速 ≥5 km/h，RPM ≥1400；
- 绝对节气门开度 ≤16%，负荷 ≤12%，均为有效数据。

保持断油估算也必须始终有状态 4；其余保持阈值为车速 ≥3、RPM ≥1100、节气门 ≤18%、负荷 ≤15%。任意条件不满足或数据失效即退出。冷车状态 1、闭环状态 2、故障状态 8/16、未知/不支持状态 0 均不得触发估算断油。

这里使用的是 PID 11 **绝对节气门开度，不是油门踏板位置**。阈值尚待实车对比，不保证所有温度、附件负荷或驾驶工况都识别准确。不会因不支持 01 03 而回到旧版仅凭低负荷强制归零的逻辑。

## 数据时效、轮询与累计

- RPM/车速有效期 3 秒；MAF、AFR、5E 为 5 秒；断油依据（状态、TPS、负荷）为 2.5 秒。均使用真实接收时间；断连、重连初始化时清除有效标志。
- 用 `01 00` 支持位判断 03；支持情况未知时最多主动尝试 3 次，避免不支持的适配器反复超时。
- ZD8 没有使用的增压、油压轮询槽改用于状态与 MAF；5E 不支持时其槽也用来更新状态。仍保留原先 4 次/轮车速查询和高优先级 RPM。填充空槽会占用少量额外串行通信时间，并不提高适配器自身吞吐量。
- 约每 200 ms 更新累计，但使用单调时钟测得的真实间隔，不再固定当作 1000 ms。**这不是宣称每个 OBD PID 都有 5 Hz 采样率。**
- 燃油、里程保留小数余量，防止短周期整数取整持续丢量。
- 超过 2 秒的任务调度空档不以一条缓存数据补算；已知过期的数据也跳过。有效期以内仍会使用最近值，不是 ECU 同步快照。
- 有效燃油数据时，怠速用油和运行时间计入当前行程及 Lifetime；缺失数据的间隔不计入这组累计统计，因而长期丢包会导致少计，需要实车验证。
- 保存仍为每 60 秒一次，进入速度为 0 的状态时额外保存一次；持续停车每分钟保存。未改变持久化格式、历史记录或 BLE 行程记录格式，也不会重算旧历史。

## 验证与局限

`python -m unittest discover -s tests -v` 编译执行实际 `fuel_estimator.c` 和缓存代码，检查 MAF 单位、ECU 零值/正值优先、开环加浓、冷车/故障、断油恢复、过期缓存、断连、不同累计间隔和一小时总量；模拟器复用同一计算模块，其演示数据未提供状态时显示 MAF，不伪造真实 ECU 断油状态。

验证固件后，应对照实车 Car Scanner 的设置与 CSV（稳定巡航、收油带挡滑行、踩离合回怠速），再比较加油量。现阶段无燃油修正系数、油品自适应或 MAF 缺失时的 MAP/IAT 备用模型；没有足够依据就不扩展到这些方法。
