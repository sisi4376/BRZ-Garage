# 鸿蒙 0.4.0 与 Android 4.3.10 对齐记录

本轮以主工作区当前 Android 4.3.10（150）源码与资源为基准，更新鸿蒙原生应用至 0.4.0（400）。内置仪表固件为 4.0.6。鸿蒙源码位于现有 `codex/harmony-app` 工作树；保留该工作树此前的未提交修改。

## 核对与变更

| 范围 | 当前结果 |
| --- | --- |
| 加油历史滚动窗口 | 仪表原始窗口与手机修订记录分开保存；超过 20 条的旧记录不因 revision 变化整批删除。完整读取后再次核对协议版本、数量、首尾 ID 和 revision，在同一事务提交 |
| 加油删除与修订 | 删除前读取最新窗口；窗口外记录只在手机合并/丢弃，窗口内节点发送仪表命令。确认同时要求 revision 改变和目标节点消失。离线请求持久化，重连执行；未发送的请求不能误当作仪表已确认 |
| 加油合并保护 | 用显示记录与原始记录的差值承接手机修订；重复同步不重复累计。最近的已修订区间缺少已完成后继时保留原记录，避免丢失手机数据 |
| 自定义行程 | 归档、新起点和待同步请求在一个 SQLite 事务中保存；离线使用明确标注的最近车辆快照及其时间。旧确认框不能重复归档 |
| 自定义保存确认 | 支持 20 字节 v2 请求/回执、CRC、请求 token、持久化标志及实际基线；旧固件写入仅标记为已发送。超时、断连、NVS 未保存后继续待确认；旧回执不能覆盖新起点 |
| 导入与重启 | 待执行命令和原始窗口不进入迁移包；导入使旧原始窗口失效并为当前自定义基线生成新的本机请求。重启从事务状态恢复 |
| 修订模式 | 加油、自定义详情默认浏览，进入修订模式才显示修改、删除、重置；退出页面恢复浏览模式 |
| 3D 车辆 | 补齐 ZD8/ZC6 离线模型、共享渲染器、前后/车牌视角、拖动缩放、六种车漆、亮面/哑光、矢量车牌与模型署名。默认关闭，已有设置和迁移外观偏好保留；失败显示 2D 并可重试 |
| 3D 资源隔离 | Web 仅从包内资源响应虚拟域名请求，禁止其他域名和路径穿越；渲染器、GLB、来源文件及许可证与当前 Android 文件逐一核对 SHA-256 |
| 后台发现 | 在“我的仪表”新增系统发现开关；API 23+ 配对并注册 PartnerAgent，系统回调核对同意状态、自动连接开关及绑定地址后进行一次有时间上限的同步。不支持的系统仍使用前台/蓝牙长时任务 |
| 前后台数据并发 | 写入前在事务内核对数据库元数据版本；新操作先重新加载另一实例已提交的数据，防止整库保存覆盖后台新记录 |
| 固件与仪表行为 | HAP 携带与当前 APK 逐字节相同的 4.0.6 镜像，包含启动卡顿修复、trip interval 直接翻页、自定义起点持久化确认。手机应用升级不会自动刷写仪表 |
| 行程、费用与保养 | 核对列表/拆分/修订/删除标记、轮询自检、离线仪表归属、未绑定费用保留、轮胎独立寿命及 50000 km / 8 年周期；此前鸿蒙修复继续保留 |
| 迁移与首页 | 保留 v1/v2 导入、v3 双向迁移、九类数据、缓存、布局/外观偏好、备份和冲突规则；当前 Android 生产编解码器参与往返测试 |
| 首次使用 | 对齐分别确认安全数据说明及版权许可说明的交互；已有有效确认继续保留 |
| 后续差异检查 | 记录当前 Android 52 个源码/配置文件基线，全套测试包含只读漂移检查。Android 发生变化时要求重新核对，不能只修改版本号便认为已对齐 |

## 验证

- 101 项鸿蒙宿主测试通过，覆盖真实 SQLite 回滚/重启、跨实例并发、超过 20 条加油历史、重复合并、旧回执、旧固件、离线删除、系统发现回调与 3D 资源访问限制。
- 当前 Android → Harmony → Android 往返通过：九类数据、偏好和仪表缓存。
- ArkTS/HAP 构建成功；最终包内核对应用 0.4.0（400）、PartnerAgent 扩展、两套 GLB 模型和固件 4.0.6。
- 签名校验通过，与原 0.3.1 使用相同证书链，沿用现有私有调试授权。
- `git diff --check -- harmony_app` 通过。

以上不代替手机和仪表实测。本轮未覆盖安装、未刷写、未发布 GitHub；3D 在 ArkWeb 中的实际渲染、API 23+ 系统唤醒、真实 BLE/NVS 回执及 OTA 仍需实机验证。HAP 安装与系统权限、配对、后台发现遵循鸿蒙流程，不使用 Android APK 安装器。旧系统不支持 PartnerAgent 时，不能获得该项系统发现能力。
