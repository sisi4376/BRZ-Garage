## 使用

1. 用 Android Studio 打开 `android_app` 目录。
2. 使用 JDK 17，并安装 Android SDK API 37。
3. 构建并安装 `app`，首次打开时允许“附近设备”；通知权限可以拒绝，不影响 BLE 同步本身。
4. 仪表上电后，点击“绑定我的仪表”，在系统列表中选择名称以 `SkyGarageRC` 或 `SkyGauge` 开头的自己的设备。后续只连接已选地址。
5. 开启自动连接，保留手机蓝牙。在连接页查看授时是否成功、是否回读校验。
6. 鸿蒙 / 华为：在应用启动管理中允许自启动、关联启动和后台活动，必要时锁定后台；安卓 10/11 还需允许后台定位以用于蓝牙发现。应用不采集 GPS。
7. 续航默认按 50 L 油箱容量估算，可在连接页校准。车辆不支持 `01 2F`、尚无油量或累计油耗样本不足 10 km 时不显示续航数字。

鸿蒙设备只要支持安装和运行普通 Android APK，就可以使用这一客户端；不支持 Android APK 的系统版本需要另做原生鸿蒙客户端，但可复用 `docs/TRIP_BLE_SYNC.md` 定义的同一套 BLE 协议。

本次测试安装包为 `android_app/BRZ-Garage-v2.0.0-debug.apk`。包名仍为 `com.brz.gauge.trips`，versionCode 升到 2。已通过 apksigner 验证，与 `BRZ-Trip-Sync-v1.0.0-debug.apk` 的证书 SHA-256 相同：`08bab8a9c07f8e5b0efcfb39f6c9ee56bea08021c7e5b231be7efff0aaa43f50`。可以覆盖安装保留历史；不要卸载旧版、清除应用数据或在签名冲突时强行重装。旧安装包保留供追溯。

## 数据安全语义

- 仪表保存最多 64 条尚未确认的完整记录。
- 客户端先校验 CRC、写入 SQLite，再向仪表发送累计 ACK。
- 断线重连会从最后 ACK 继续，同一条记录按仪表地址和行程 ID 自动去重。
- 历史记录在手机端不设条数上限；更换或清除应用数据会删除手机本地历史。
- 升级前生成的旧记录没有可信墙钟时间，仍会同步，但界面显示“时间未知”。

### 手机实测清单

1. 覆盖安装后确认旧行程仍在。首次允许附近设备、通知，绑定自己的仪表。
2. 连上后首页显示“授时已回读校验”；旧固件显示“仅写入确认”，需要配套升级。

6. 对照实车油量、加油后的变化与续航估算；无信号应显示不可用，断开后显示上次快照。
7. 手机同步过程中断开 BLE 后重连，检查历史没有重复或丢失。
