# OBD Studio Android

独立的 Android BLE OBD 数据采集、查看和仪表回放工具。Android 8.0+，包名 `com.brz.obdstudio`，可与 BRZ Garage 同时安装。当前公测版 **1.0.0-beta.12**，支持扫描选择 OBD 和一键双阶段采集。

安装 [1.0.0-beta.12 APK](https://github.com/sisi4376/BRZ-Garage/releases/download/v4.6.7/BRZ-OBD-Studio-Android-v1.0.0-beta.12.apk)（[SHA-256](https://github.com/sisi4376/BRZ-Garage/releases/download/v4.6.7/BRZ-OBD-Studio-Android-v1.0.0-beta.12.apk.sha256)），可使用原签名覆盖安装。上一公开版为 [1.0.0-beta.4 APK](https://github.com/sisi4376/BRZ-Garage/releases/download/v4.6.6/BRZ-OBD-Studio-Android-v1.0.0-beta.4.apk)（[SHA-256](https://github.com/sisi4376/BRZ-Garage/releases/download/v4.6.6/BRZ-OBD-Studio-Android-v1.0.0-beta.4.apk.sha256)）。首次操作按系统提示授予蓝牙／附近设备权限；Android 11 及以下扫描还需要定位权限与系统定位开关。通知权限用于显示后台任务和停止入口。

beta.12 修复实时页显示百分比读数时的闪退，包括发动机负荷、节气门和燃油余量。

## beta.11 初始化收发修复与闪退诊断

针对开始采集即显示 `ATZ` 超时、接收 0 字节的情况，通道选择对齐仪表：在 FFF0、18F0、FF12 的优先级下，按发现顺序选择第一个可写特征和第一个带 CCCD 的 Notify 特征，不再硬性优先 FFF2；无 Notify 时兼容 Indicate。订阅完成后按仪表流程等待 300 ms。初始化用 ATZ 加 ATE0 的完整应答验证双向收发，不能仅凭 GATT 连接、订阅或写入成功判定 ELM 就绪。

初始化无回复或写入被拒绝时，释放原 GATT 连接后验证其他符合属性的通道／写入方式，最多 8 个组合。每次重新连接并订阅，旧连接回调丢弃，保留每次尝试的收发原文、通道、写入类型与状态。收到不完整响应、ELM 拒绝 ATE0 或进入 PID 轮询后失败时仍保存并停止，不在同一连接上重复超时命令。

界面与运行日志显示安装版本。采集异常会在未完成 JSONL 中保存异常堆栈；真正的 Java/Kotlin 未捕获异常另存 `last-app-crash.jsonl`，重开 App 后可从文件页“导出所选原始录制”导出。该文件仅用于诊断，不能回放，没有统计摘要；不会自动上传。系统直接杀进程或原生崩溃不保证留下此文件。升级可覆盖安装，已有录制保留。

已完成模拟 GATT 的同特征通知、多通知特征、备用写入、重连切换、部分响应和轮询超时检查，以及协议／文件回归；真实手机与该 ELM 的互通仍待验证。

## beta.9 蓝牙连接修复

针对“可扫描到 ELM，但开始采集后连接失败”改进连接流程：每次连接前重新扫描并确认已选地址，使用这次扫描返回的 BLE 设备建立连接，保留设备地址类型信息；不会改连附近同名设备。GATT 连接失败时先释放连接，等待 1 秒后重新确认同一设备，最多重试一次。未发现该地址时明确提示重新扫描选择，避免一直使用失效地址。

保留 FFF0、18F0、FF12 优先级，兼容同特征写入/通知、Indicate 通道和带 CCCD 的唯一自定义串口服务；未知服务有多个候选时不会盲选。Android 13+ 使用带独立数据参数的写入接口；有响应和无响应写入都等待 Android 完成回调，失败状态会显示。初始化前记录并清理连接启动横幅，后续请求不清理迟到数据。

界面日志区分重新确认设备、GATT 连接、服务发现、订阅和 ELM 初始化。原始录制新增 `ble_event` 和 `ble_inventory`，保留连接状态码、尝试次数、服务及特征清单。失败片段可在“文件”页导出 JSONL；即使没有实时采样，诊断信息仍然保存，但该文件不能作为数据回放样本。

安装后重新点击“扫描并选择 OBD”，确认选择车上的 ELM，再开始采集。让仪表和其他 App 先断开 ELM；若仍失败，请提供日志最后的错误文字，或导出此次未完成 JSONL。已完成模拟 GATT 回调测试、现有功能回归、APK 编译和静态检查；真实手机与该适配器的连接仍待联调。

## 与电脑版功能对应

| 电脑版功能 | Android 入口 |
|---|---|
| 一键双阶段采集（Android） | 采集 → 扫描并选择 OBD、选择车型 → 一键采集 |
| BLE 扫描、按地址连接 | 采集 → 扫描并选择 OBD；高级手动采集也可填写地址 |
| FFF0、18F0、FF12 适配器 | 按相同优先级自动选择写入／通知特征 |
| 四车型仪表轮询 | 一键流程的第二段；或高级手动采集范围前四项：ZD8/ZC6，6MT/6AT |
| 全量保留模式、常用 PID、旧 ZC6 精简模式 | 高级手动采集范围其余选项 |
| 额外只读请求、时长、请求间隔 | 高级手动采集；仪表同款模式固定调度，不接受额外命令 |
| 转速、车速、水温、油温 | 实时页，含 ZC6 `2101` 完整多包油温解析 |
| 瞬时／平均油耗、里程、耗油、油量、总里程、电压 | 实时页，区分 ECU 数据与 MAF 汽油估算 |
| 原始请求／通知分包／完整响应 | JSONL 保留原始十六进制字节和单调时间戳；实时页显示每个请求最新响应与年龄 |
| 最近 60 秒转速曲线与日志 | 实时页及各页底部日志 |
| 保存 JSONL 和统计摘要 | 默认应用本地；每段结束各保存两份文件，选择自动导出文件夹后同时复制 |
| 导入、导出文件 | 文件页；导出原始 JSONL 或 `.summary.json` |
| 0.25～4 倍速、循环回放 | 回放页；支持导入电脑版 JSONL |
| 通过 BLE 回放到实体仪表 | 启动回放后，仪表 BLE SCAN 选择手机的 FFF0 服务 |
| 停止任务并保存 | 底部固定按钮，或前台服务通知的停止按钮 |

## 使用

1. 让其他 App 和仪表断开车上的 ELM327。开启手机蓝牙，在采集页点击“扫描并选择 OBD”，约 8 秒后从扫描结果中点选适配器；也可提前点击“结束扫描并选择 OBD”。列表显示设备名称、地址和信号强度，同名或未命名设备可通过地址区分，不会自动选中信号最强设备。再选择 ZD8/ZC6 的 6MT 或 6AT 车型，点击“一键采集（各 5 分钟）”。所选设备的名称、地址及车型自动记住；下次可直接开始，设备更换或地址变化时重新扫描。beta.5 升级用户需要先扫描选定一次。
2. 自动执行“全部支持的标准 PID 5 分钟 → 所选车型轮询 5 分钟”，每段连接和初始化完成后单独计时，段间自动保存、断开并重新连接。正在等待的最后一条请求可以完成后再结束，因此加上扫描、初始化和切换，总用时会超过 10 分钟。实时页和通知显示阶段与计时。
3. 每段生成独立 JSONL 和统计摘要，正常完成共四份文件，以同一任务编号关联。用应用或通知中的“停止并保存”可提前结束；中断、连接失败或支持列表读取失败时保留已采集片段，标记未完成，不继续下一段。第一段只遍历 ECU 声明支持的标准 PID；某项的实际采样次数由响应速度和支持数量决定。
4. 文件默认保存在应用私有目录；需要拷到电脑时在文件页导出。也可在采集前选择自动导出文件夹，每段结束自动复制录制和摘要；导出失败时仍保留本地文件。卸载前先导出需要保留的文件。关闭界面或切到后台后任务继续；系统强行停止、应用被系统杀死或断电不保证写出最终摘要，但已经逐行刷新的 JSONL 仍保留此前数据。
5. 单独录制、自定时长、按地址连接等操作在“高级手动采集”中设置。
6. 回放时选择本地或导入的 JSONL，设置速度和循环，然后启动。在仪表扫描页选择这台手机，等待仪表实时请求。手机蓝牙名称过长时广播可能只显示地址或未知设备，请结合 FFF0 服务辨认。

录制使用与电脑版相同的 schema 1。手机、电脑可以相互回放；旧文件没有统计摘要也能导入。文件末尾因中断留下的不完整行在加载时忽略，其余格式损坏会报错。原始文件导出保持内容不变。回放时间轴从第一次实时请求开始，每个仪表独立计时；ATZ 不重启时间轴，断线重连从头开始。未知请求、不同 ECU 请求地址和 ATH1 请求返回 NO DATA，不注入静态假数据。回放采用 20 字节通知分包并等待每次通知完成。

全量模式没有总录制时长或样本年龄限制，保留最近采样值；累计里程和耗油按该值保持到下一份响应，属于采样间隔估算。其他模式统计样本有效期为 5 秒，卡片超过 15 秒未更新显示空值。平均油耗至少需要 10 米共同有效里程。`015E` 仅记录以供对照；耗油量使用 MAF 和指令 λ 估算。6MT 和 6AT 使用相同的断油进入与保持条件，状态缺失时需低负荷、低进气量同时持续 400 ms；即使全量模式保留采样，也不使用过期证据判零。详见[本地固件的计算规则](../../docs/FUEL_CALCULATION.md)。

四车型模式与仪表固件 4.1.4-beta.6 共用 A/B 排布。两组都查转速、车速和 MAF。A 组另查节气门、负荷、燃油系统状态（已知不支持时改查指令 λ）。B 组另查指令 λ、点火提前角和一项慢数据。慢项依次为进气温度、水温、油温、电压、油箱液位、直接燃油流量和支持位。ZC6 油温 `2101` 和支持位 `0140` 在对应 B 组后单发。同一组连续两次收到不合格回包，该组改为单项查询，另一组独立运行。

所有采集命令顺序等待 `>`，查询超时后保存并停止，防止迟到响应错配。全量指 ECU 声明支持的标准实时 PID 以及实际收到的 ELM 数据，不代表整车 CAN 总线全部报文。不支持经典蓝牙 SPP、Wi-Fi ELM 或被动 CAN 监听。

蓝牙回放要求手机支持 BLE 外设广播，系统或硬件不支持时会显示错误。前台服务维持后台任务，不代表能绕过厂商省电策略；设备端的扫描、熄屏采集、广播、订阅与实际仪表显示仍需实机验证。

## 验证与构建

已完成 beta.8 APK 编译、版本与原签名核对，以及 Android 生产 Kotlin 代码与电脑版的 核心对照检查，覆盖四车型调度、统计、ZC6 油温、JSONL 双向读写、时间轴、倍速、循环、分包、请求边界和错误值。另以实际设备选择和启动方法验证必须主动点选、名称与地址保存、同名／未命名设备区分及采集使用所选地址；实际服务的录制／保存方法覆盖双阶段文件落盘、提前停止、第二段连接失败与自动导出失败，车型和时长计划亦有主机测试。不应把这些检查当作已完成实车或手机测试。

在 `android_app` 工程运行 `:obd_studio:assembleDebug`，生成独立模块 APK；采用项目现有本地调试签名。测试运行 `python -m unittest discover -s tests -p test_obd_studio_android.py`，需要项目 Kotlin/JDK 和 `.toolchains/obd-studio-test/json-20250517.jar` 测试运行库。
